### 分かったこと

1. **第1段階だけでは読めるようにならない。** 16章は文を分割しても漢字率が動かず、

   16章では追加規則が届いた時点で第1段階が終わっており、反映されなかった
4. **一文平均の測定には表が混ざる。** 表の行を1文として数えると数値が悪く出る。
   地の文だけなら 50字前後まで下がっている

## 残り27章への進め方

### 1エージェント = 1章。ただし内部で2段階に分ける

指示にこう書く:

> **まず第1段階（文を割る・漢字を開く）を全節に適用し、ファイルに保存してください。**
> **その後で、第2段階（具体化）を全節に適用してください。**
> 同時にやろうとすると、必ず第2段階が疎かになります。

### 並列度は5本まで

過去にセッション上限で全滅した経験がある。5本ずつ、完了を待って次を出す。

### 順序（読者が最初に読む章から）

| 波 | 章 | 理由 |
|---|---|---|
| 1 | **1, 2, 3**（第1部） | 読者が最初に読む。ここで脱落すると本全体が読まれない |
| 2 | **13, 14, 15**（第4部） | 迎えた直後に読む。最もつらい時期 |
| 3 | **17, 18, 19, 20**（第5部） | 依頼者が最重視した吠え・噛み |
| 4 | **10, 11, 12, 8, 9**（第3部） | 迎える前の意思決定 |
| 5 | **21, 22, 23, 24**（第6部） | 健康。医療用語が多い |
| 6 | **25, 26, 27**（第7部） | 看取りを含む。トーンに注意 |
| 7 | **4, 5, 6, 7**（第2部） | 知識編。**依頼者の指摘（楽観バイアス）はここ**なので優先度を上げてよい |
| 8 | **28**（第8部） | 保険。数値が多い |

### 各章で変えてはいけないもの（全章共通）

- 数値・出典・脚注番号・エビデンスバッジ
- 「確認できていない」「裏が取れなかった」という留保
- 章の構成・節の順序・見出し
- コンポーネントの構造
- frontmatter
- **医療・法律の章では、用量・条番号・罰則額・期限を1文字も変えない**

### 完了の判定

- `pnpm build` が通る
- 字数が **+5%以上** 増えている（具体例が足された証拠）
- `items={[...]}` の中にコンポーネント・Markdown記法がない
- 医療/法令章は、数値の grep 照合が一致する

## 失敗の記録: 同じ章に2つのエージェントを走らせた

記録日: 2026-08-27

### 何が起きたか

16章と29章で、**同じ「具体化」作業をするエージェントを二重に起動した。**

経緯:
1. 第1段階（文を割る・漢字を開く）のエージェント P1 を起動
2. 作業中に依頼者から追加の指摘（「楽観的な判断のかたより」が分かりにくい）
3. 追加規則6〜8を書き、**走っている P1 にメッセージで送った**
4. 同時に、**第2段階専用のエージェント P2 も起動した**
5. P1 はメッセージを受けて第2段階を実行し、完了
6. P2 は起動後、ファイルに「自分がやっていない変更」があることに気づいて確認を上げてきた

### 原因

**走っているエージェントにメッセージを送ることと、新しいエージェントを起動することを、
同じ目的で同時にやった。** メッセージが届いて実行されることを勘定に入れていなかった。

### 被害

なかった。**両エージェントとも「編集のたびに再読してから Edit する」手順を取っており、
かつ自分から競合を報告してきたため。**

### 今後の規則

1. **走っているエージェントに追加指示を送ったら、同じ範囲で新しいエージェントを起動しない。**
   どちらか一方にする
2. 追加指示を送る場合は、**そのエージェントが完了報告を出すまで待つ**
3. 完了報告を見てから、不足があれば改めて1本だけ起動する

### 副次的に分かったこと

**エージェントが「これは重複では?」と確認を上げてくる設計は有効だった。**
指示に「迷ったら確認する」を明示しておくと、事故が防げる。
今後の執筆指示にも、この一文を残す。
