# 設計判断ログ 09: 章をまたぐ参照をリンクにする

記録日: 2026-08-26

## きっかけ

18章を書いた執筆エージェントから、こういう報告があった。

> 法令章・第16章・第20章への参照は章番号のみ（既存章に倣い「第○章」表記）で、
> **リンクは張っていない（自動リンク機構が見当たらないため）**。

本文を調べると、章をまたぐ参照が **49箇所**あった（「第7章」だけで20回）。
素のテキストのままだと、読者は目次に戻って章を探す必要がある。

## 実装

`src/lib/rehype-chapter-links.mjs` を書き、`astro.config.mjs` の
`markdown.rehypePlugins` に登録した。

### 設計上の判断

1. **章番号 → ファイル名の対応は、ファイル名から作る**
   `src/content/chapters/NN-slug.mdx` という命名規則があるので、
   frontmatter を読まずにファイル名だけで対応が取れる。速く、依存も少ない。

2. **まだ存在しない章はリンクにしない**
   これが最も重要な判断。本書は執筆途中で、29章のうち9章しかない。
   存在しない章番号（第20章、第24章、第26章など）をリンクにすると、
   **リンク切れになる**。存在するものだけをリンクにし、残りは素のテキストのまま残す。
   章が書かれれば、次のビルドで自動的にリンクになる。

3. **`<a>` と `<code>` の中は対象外**
   二重リンクと、コード例の破壊を防ぐ。

4. **見た目は下線ではなく淡い下地**
   本文中に49箇所も下線リンクが入ると、可読性が落ちる。
   `.xref` クラスで、アクセントカラーの薄い下地にした。

## 結果

- **32箇所がリンク化**（04章2、06章3、07章1、13章5、17章10、18章11）
- 存在しない章（第20章・第26章）は**リンクされていない**ことを確認済み
- 章を書き足すたびに、既存章からのリンクが自動的に増える

## 副次的な効果

この仕組みができたことで、執筆エージェントに「章参照はリンクにしてください」と
指示する必要がなくなった。**本文には「第7章」と書くだけでよく、リンク化はビルドが行う。**
執筆時の負担を増やさずに、読者の利便性だけが上がる。
