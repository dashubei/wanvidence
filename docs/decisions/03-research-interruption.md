# 設計判断ログ 03: 調査の中断と、その扱い

記録日: 2026-08-26

## 何が起きたか

18本の調査エージェントを並列起動したが、以下の2つの制約により14本が中断した。

1. **WebSearch のセッション予算枯渇（200/200）**
   予算はセッション全体で共有されており、並列エージェントが早い段階で使い切った。
   各エージェントが使えたのは平均10回程度。
   セッション上限がリセットされても、**WebSearch 予算は回復しない**ことを確認済み。

2. **セッション使用量上限**
   予算枯渇後、WebFetch にフォールバックして作業を続けていたエージェントも、
   セッション上限で強制終了された。

## 学んだこと（今後の並列調査への教訓）

**18本を同時起動したことが、WebSearch 予算枯渇の直接の原因**である。
予算がセッション全体で共有される以上、並列度を上げるほど1本あたりの
検索回数が減り、全体の品質が下がる。

次回以降の方針:
- **一度に走らせる調査エージェントは4〜6本まで**にする
- 各エージェントに「WebSearch は最大N回まで」と明示的な上限を与える
- URL が既知の一次情報（PubMed、学会公式、e-Gov、環境省、自治体）は
  **WebSearch を使わず WebFetch で直接取得する**よう指示する
  （R07 はこの方法で英国の電気首輪規制の誤情報を訂正できた）
