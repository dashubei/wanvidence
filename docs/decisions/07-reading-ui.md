# 設計判断ログ 07: 長文を読むためのUI

記録日: 2026-08-26

## 何が問題だったか

執筆した章は1章あたり44〜74KB ある。画面上でこの分量を読むと、
**いま章のどのあたりにいるのか分からなくなる**。

初期実装では章内の見出し目次を折りたたみ（`<details>`）でページ冒頭に置いていたが、
これはスクロールすると視界から消える。つまり「読み始める前」にしか使えない。

## 何をしたか

### 1. 画面が広いときは、見出し目次を本文の横に常駐させる

グリッドを段階的に増やす:

| 画面幅 | 構成 |
|---|---|
| 〜68rem | 本文のみ（章ナビはドロワー） |
| 68rem〜 | 章ナビ + 本文 |
| 92rem〜 | 章ナビ + 本文 + **章内見出し** |

92rem 未満では折りたたみ目次を出し、92rem 以上では横目次を出して折りたたみを隠す。
両方を同時に見せない（同じ情報が二重に出ると、どちらを見ればよいか迷う）。

### 2. いま読んでいる見出しを目次で示す

`IntersectionObserver` で、`rootMargin: '-72px 0px -72% 0px'` を使い
**画面上部に最も近い、見えている見出し**を現在地とする。
下端を -72% にしているのは、画面下部に入ってきただけの見出しを
現在地にしてしまわないため。

### 3. 読み進み具合を細い線で示す

ヘッダの直下に 2px の線を置き、スクロール量に応じて伸ばす。
`requestAnimationFrame` でスロットルし、スクロールイベントは `passive: true`。

CSS の scroll-driven animation（`animation-timeline: scroll()`）でも書けるが、
対応ブラウザが限られるため JS で実装した。

### 4. 先頭に戻るボタン

600px 以上スクロールしたときだけ表示。
`prefers-reduced-motion` を尊重し、その設定なら瞬時に移動する。

## 検証

`python3 -m http.server` で dist を配信し、curl で確認した。

- 全11ページが 200
- Pagefind の検索インデックスが生成されている（index 4ファイル、fragment 5）
- 07章の横目次に40見出しが入っている
- 見出しの id は日本語スラッグ（`#3-ladder-of-aggression--咬むまでに犬が登るはしご`）

## やらなかったこと

- **章内の読了状態の保存**: チェックリストは保存するが、
  「どこまで読んだか」は保存しない。読み返しの多い参照文書では、
  前回の位置に飛ばされるより、毎回先頭から見えるほうが扱いやすいと判断した。
- **スクロール連動のアニメーション**: 長文の可読性を下げるため入れない。
